# 0001: Foundation of the Bricks website

**Status:** Decided (2026-11-20), by the owner.

**Context:** ProBiz CMS 1.0.0 runs on Bricks's VPS (`admin.bricks.ba`, `api.bricks.ba`). The public website, `bricks.ba`, is a separate project in this repository (ProBiz CMS docs/decisions/0013 item 3, 0054, 0052 O8). The design is a prototype ("Bricks Prototype": site, order, tokens, fonts, illustrations). The site talks to the CMS only through its public API and `@probiz/sdk`.

## Decisions

| #   | Topic                   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | Scope of v1             | Everything: the homepage, ordering from the table, the franchise, the legal pages and SEO.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| F2  | Languages               | `bs` (ijekavica, Latin script) is the default and has no URL prefix. `en` lives under `/en/...`. The list of languages comes from the CMS.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| F3  | Content                 | CMS pages made of blocks, edited by Bricks. Block components map 1:1 to the API's block types; one the theme does not know is skipped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| F4  | Franchise               | No route code of its own. A venue is a `locations` record (ProBiz CMS 0052 O2). The homepage and a venue's page (for example `/tuzla`) are ordinary CMS pages of blocks. While there is one venue, the homepage is that venue's page. When a second opens, Bricks makes its page (`/bijeljina`) and puts a `locationList` block on the homepage as the venue chooser. Blocks that show a venue's data (menu, events, address, hours) use `locationId` where the API offers it. Where a block schema has no location field, the gap is written down and proposed as a CMS change, not worked around in the theme. |
| F5  | Ordering from the table | The route `/s/[token]` is fixed: the CMS prints `{websiteUrl}/s/{token}` on the table's QR code. The server renders the table page (`GET /v1/public/ordering/tables/:token`), never cached and `noindex`; an unknown code shows an "invalid QR code" page.                                                                                                                                                                                                                                                                                                                                                       |
| F6  | The guest's secret      | The basket is a client component. The guest's `guestSecret` is kept in `localStorage`, per order, and removed when the order is paid or cancelled, or after 12 hours, so the status survives a closed tab.                                                                                                                                                                                                                                                                                                                                                                                                       |
| F7  | Calls to the guest API  | The browser calls the guest API **directly** on `api.bricks.ba` (the API's CORS allows `SITE_URL`, ProBiz CMS 0054 S6), not through the site's server: through the server every guest would share one address in the per-address rate limit. Only `itemKey`, `priceIndex`, `qty`, `note` and `locale` are sent, never prices. Live status is read with a `fetch` reader of the SSE stream and falls back to polling.                                                                                                                                                                                             |
| F8  | Tests                   | Unit tests with Vitest. Playwright (1440 x 900 and 390 x 844, screenshots in `test-results/`) runs against a **fixture API**, a small Node server in `e2e/support/` that returns JSON in the shape of the SDK's types. The CI of this repository cannot pull the CMS's private images, and the run stays deterministic.                                                                                                                                                                                                                                                                                          |
| F9  | Deploy                  | As ProBiz CMS 0054 S2 to S5: its own Compose project on the server next to the CMS, joining only the `probiz-edge` network, behind the CMS's Caddy. The image is built from this repository (`ghcr.io/neramsoft/bricks-site`) and deployed by hand with `deploy-site`. Revalidation uses the signed webhook of Settings, Website connection.                                                                                                                                                                                                                                                                     |
| F10 | The SDK                 | `@probiz/sdk` is an npm alias of `@neramsoft/probiz-sdk` from GitHub Packages (private). `.npmrc` is committed and names `${NPM_TOKEN}`; the token (classic, `read:packages`) comes from the environment and is never written to a file. CI uses `GITHUB_TOKEN` with `packages: read`, which needs Read access of this repository to both packages. The image build uses a BuildKit secret.                                                                                                                                                                                                                      |
| F11 | Lowest CMS version      | 1.0.0.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| F12 | Repository and workflow | Single package (pnpm 11, Node 24), not a monorepo. Branches, commits and PRs as in ProBiz CMS: `feature/*` and `fix/*` from `development`, squash PRs, `development` to `master` by release PR, conventional commits, commits by the owner only with no trailers.                                                                                                                                                                                                                                                                                                                                                |

## Order of work

1. `feature/scaffold`: tooling, settings, health check, CI, image, repository docs.
2. `feature/cms-pages`: catch-all route, proxy (redirects, 410, 404), cached CMS clients, languages, breadcrumbs, metadata, JSON-LD, robots, sitemap, revalidation webhook, preview.
3. `feature/theme-and-blocks`: the design, fonts, header and footer, the blocks.
4. `feature/table-ordering`: `/s/[token]`.
5. `feature/deploy`: Compose, Caddy snippet, release workflow, runbook.

## Consequences

- No Bricks content or code goes into ProBiz CMS. Gaps found here are proposed as CMS changes.
- The site depends on the public API only, so a CMS release never forces a site release within a major version (0054 S3).
