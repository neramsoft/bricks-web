## The 404 finding

PR 2 found that the 404's status was right but its body was not in the first HTML. Reproduced: `/missing` called `notFound()` and drew the page in `not-found.tsx`; the response was `<html id="__next_error__">` with an empty body, and the page existed only in the RSC data that the browser draws from. The same happened with a trivial `not-found.tsx` that reads nothing, so it is not the data the page reads. The cached page route's own `notFound()` (a page gone between the proxy and the render) does draw its body in the HTML, so the cause is `notFound()` from a segment that is its own root layout.

Fix: `src/proxy.ts` rewrites a missing address to `/missing/...` with `status: 404`, and `src/app/missing/[[...route]]/page.tsx` draws the 404 itself (`NotFoundView`: chrome, heading, text, link home, `<title>`, `noindex, follow`) and reports the visit in `after()`. The proxy's rewrite sets `x-site-path`; a direct visit to `/missing/...` has no such header and is a plain `notFound()`. Next adds its own `noindex` meta to a 404 too, so the first HTML names `noindex` twice, once with `follow`. Tested in Playwright by asserting the text, the title and the meta in the raw HTML of `request.get`.

## Franchise: which blocks can be scoped to a venue (F4 of docs/decisions/0001)

A venue is a `locations` record. The checks are against the block schemas of `@probiz/blocks` 1.0.0 and the public API.

| Block                         | Venue scope                                                                                                                               |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `eventList`                   | **Yes**: `locationId`.                                                                                                                    |
| `jobList`                     | Yes: `locationId` (not drawn by this site).                                                                                               |
| `restaurantMenu`              | By record: the block names one menu (`menuId`) and a menu belongs to one location, so a venue's page names its own menu.                  |
| `restaurantMenuList`          | **No**: the API's list takes `locationId`, the block has no field for it, so a venue's page lists every venue's menus.                    |
| `locationList`                | **No**: no filter and no hand-picked list, only `limit`. The franchise page can list all venues, a venue's page cannot list "the others". |
| `openingHours`                | **No**: always the business's hours (Settings). A second venue's page would show Tuzla's hours.                                           |
| `contactInfo`                 | **No**: the business's details; `addressIndex` picks one of the business's addresses, not a venue.                                        |
| `map`                         | By value: the block holds its own coordinates and label, so it can be set per venue by hand. Its address line is the business's address.  |
| `contactForm`                 | **No**: a form submission does not say which venue it is for.                                                                             |
| `galleryEmbed`, `galleryList` | **No**: galleries have no location; `galleryEmbed` picks an album by id, `galleryList` lists all.                                         |
| `hero`                        | **No**: the "now" line is the main venue's (`primary`).                                                                                   |

## Gaps for the owner (CMS proposals, not worked around in the theme)

| #   | Gap                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Proposed CMS change                                                                                                                            |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| G1  | Business-level blocks cannot take a venue. Hours, contact details and the "now" line come from the business settings or the main venue, so a second venue's page would show the first one's.                                                                                                                                                                                                                                                        | `locationId` on `openingHours`, `contactInfo` and `hero` (or a "this page's venue" on a page), reading the location's own hours.               |
| G2  | `restaurantMenuList` and `locationList` cannot be scoped or picked.                                                                                                                                                                                                                                                                                                                                                                                 | `locationId` on `restaurantMenuList`; `locationIds` (hand-picked, ordered) and `excludeCurrent` on `locationList`.                             |
| G3  | A venue card (`locationList`) links only to the locations module's own detail page, which this site does not draw (F4: the venue's page is an ordinary CMS page, `/tuzla`). With detail pages off the card has no link, so the venue picker leads nowhere.                                                                                                                                                                                          | A page link on a location record (`pageId`), which the API resolves into the summary's `href` when the module's detail pages are off.          |
| G4  | The public menu answer has no item type, so the header's two buttons cannot be "of type button" as the prototype's spec says (`MenuItemInput.type` is `page`, `url` or `post`). The theme draws the **last two** header items as the buttons (`lib/header-menu.ts`).                                                                                                                                                                                | A `button` style (or `kind`) on a menu item, in the admin and in `PublicMenuItem`.                                                             |
| G5  | Menu items have no ABV and the dietary marks are the five of the CMS (`vegan`, `vegetarian`, `gluten_free`, `lactose_free`, `halal`), so "točeno", "0% alkohola", "domaći" and the percentage of a beer cannot be shown as labels. The prototype's notes go into the description.                                                                                                                                                                   | A free `labels` list and an `abv` number on menu items.                                                                                        |
| G6  | The brand fonts of the CMS are a closed list that has neither Bricolage Grotesque nor DM Sans, so the site's fonts are files in this repository and the CMS's font setting is not read.                                                                                                                                                                                                                                                             | Self-hosted fonts per site, or a custom font in Settings, Brand.                                                                               |
| G7  | `PublicEventSummary` (what an `eventList` block resolves to) has no performers, so the wide card of the next event can show "Svira" only by reading the full event (`GET /v1/public/events/by-slug/{slug}`), which exists only for an event with a detail page (`href` not null). An event without a page shows no "Svira" line. The theme reads the full event for the next event only, through the cached client, and does nothing else about it. | `PublicEventSummary` includes the performers' names (`performers: string[]`).                                                                  |
| G8  | The CMS does not reserve `s` (nor `missing`) as a top-level page slug, so an editor can create a page `/s` with children that shadow table codes (`/s/<token>`, printed on the QR codes). The site answers `/s/...` itself and never reaches the CMS's page there.                                                                                                                                                                                  | Add `s` to `RESERVED_TOP_LEVEL_SLUGS` (`apps/api/src/pages/slug.ts`).                                                                          |
| G9  | The only way to know whether a table code is unknown is `GET /v1/public/ordering/tables/:token`, which builds the whole menu. The site needs the answer before it renders, to give an invalid code a real 404 (docs/decisions/0003 T4), so each visit reads the page twice (the proxy discards the menu).                                                                                                                                           | A cheap check: `HEAD` on the table route, or `GET /v1/public/ordering/tables/:token/exists`.                                                   |
| G10 | The table page is read by the site's server, so every guest has the site server's address in `TABLE_READ_PER_IP` (3000 per 10 minutes, doubled by G9). A busy evening in several venues could reach it, and the page then says "try again". Orders and calls are sent by the browser and are not affected.                                                                                                                                          | Let a trusted site pass the guest's address (a signed header, as for form submissions), or count reads per table token instead of per address. |

## Consequences

- The CMS's brand colours must be set to the prototype's brick (`#B4492E`) and amber (`#E0A33B`), or the site takes whatever the brand holds.
- The first venue page and the homepage are the same page while there is one venue (F4). G1 to G3 matter from the second venue on.
- The sample menu and events in `e2e/support/fixtures.ts` come from the prototype's data and are test data; they are never shipped as content.
